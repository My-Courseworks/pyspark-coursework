# ShopCo PySpark Lab

A working PySpark system you can run on a laptop and on Google Cloud, built to go with the
[PySpark coursework](../syllabus.md) (this folder is its runnable half). It generates
ShopCo's clickstream at any size, runs the churn feature pipeline from the course, and records
every step (jobs, tasks, bytes shuffled, skew) in a ledger and a report.

```
lab/
  src/shopco/        the one package that runs everywhere (local/adr/0004)
    config.py        scale ladder: test 100K · smoke 2M · local 500M · cloud 2B events
    generate.py      synthetic ShopCo data, generated by Spark itself
    pipeline.py      the churn feature pipeline (course M2/M3 as code)
    monitor.py       per-step ledger from Spark's REST API + structured stdout
    report.py        ledger -> Markdown report
    cli.py           python -m shopco generate|pipeline|all|report
  tests/             end-to-end test at tiny scale (pytest, ~15 s)
  local/             laptop: setup, run scripts, History Server, ADRs
  gcp/               Google Cloud: infra scripts, submit, workflow, monitoring, ADRs
```

## Quick start (laptop)

```bash
local/scripts/setup.sh            # Java 17 via Homebrew, uv venv, package
source local/scripts/env.sh
.venv/bin/pytest                  # proves the code at 100K events
local/scripts/run.sh all smoke    # 2M events, ~15 s, prints the report
local/scripts/run.sh all local    # 500M events, minutes; Spark UI at http://localhost:4040 while it runs
local/scripts/run.sh pipeline local --keep-junk   # same data, bot key kept: watch the skew column
local/scripts/history_server.sh   # replay any run at http://localhost:18080
```

Reports land in `runs/<run id>/report.md`; the raw ledger is `runs/<run id>/ledger/*.json`.

## Quick start (Google Cloud)

```bash
gcp/infra/00_project.sh … 60_orchestration.sh   # once; see gcp/README.md
gcp/submit.sh all smoke     # 2M events on Dataproc Serverless, cents
gcp/submit.sh all cloud     # one ShopCo month: 2B events, a few dollars
```

## What "huge" means here, with measured runs

| scale | events | where | measured | Parquet | pandas could? |
|---|---|---|---|---|---|
| smoke | 2M | laptop | 12 s | 25 MB | yes |
| smoke | 2M | Dataproc Serverless | 72 s (+ ~1 min cold start) | 25 MB | yes |
| local | 500M | laptop (12 cores, 24 GB) | **61 s** | 5.3 GB | no (~30 GB in memory) |
| cloud | 2,010M | Dataproc Serverless, ≤32 executors | **17.8 min**, 7.95 DCU-hours ≈ $0.50 | 25.6 GiB | no |

The full reports are in [examples/](examples/): per-step jobs, tasks, bytes, shuffle, spill and skew ratio for each run. The 2B-row run shows what the laptop cannot: 25× skew on the purchases materialisation and 5.5× on the feature write, 3.3 GB shuffled, 12,450 tasks.

The data has the same shape at every size: NULL users, one bot key with 3% of traffic, skewed users and products, a products table too wide to auto-broadcast. See `local/adr/0001` and `0002`.
