# PySpark Coursework

A short course on PySpark for data scientists, plus a working lab that runs the course's example at scale, on a laptop and on Google Cloud.

The course answers the questions an interviewer actually asks: what happens when you call `.count()`, why a job is slow and what to check first, when to use MLlib versus plain sklearn. The lab proves the answers with code you can run: it generates a 2-billion-event clickstream, runs the churn feature pipeline from the course, and records every step's jobs, tasks, shuffle bytes and skew in a report.

## The course (`modules/`)

Five modules around one running example, **ShopCo**: an online retailer with ~2 billion clickstream events a month and a churn model to build.

| # | Module | Question it answers |
|---|---|---|
| M1 | [Mental model](modules/01-mental-model/README.md) | What actually happens when I call `.count()`? |
| M2 | [DataFrame API for DS work](modules/02-dataframe-api/README.md) | How do I write feature engineering that Spark can optimize? |
| M3 | [Performance: shuffles, skew, joins](modules/03-performance/README.md) | Why is my job slow, and what do I check first? |
| M4 | [ML at scale](modules/04-ml-at-scale/README.md) | When do I use MLlib, pandas UDFs, or no Spark at all? |
| M5 | [Interview talk-track](modules/05-interview-talk-track/README.md) | What do I actually say? |

Every module has an opening scene, the concept, a worked example on ShopCo, a paper-based design exercise, and a "tradeoff ledger" line you can quote. Terms are defined at first use, so a Spark beginner who knows pandas can follow.

## The lab (`lab/`)

One Python package (`shopco`) that runs unchanged on a laptop and on Dataproc Serverless. Measured:

| scale | events | where | wall time | cost |
|---|---|---|---|---|
| smoke | 2M | laptop | 12 s | – |
| local | 500M | laptop, 12 cores | 61 s | – |
| smoke | 2M | Dataproc Serverless | 72 s | cents |
| cloud | 2.01B | Dataproc Serverless | 17.8 min | ≈ $0.50 |

What it includes:
- **Synthetic ShopCo data** generated by Spark itself, with the quirks the course teaches: NULL users, a bot key with 3% of traffic, skewed users and products, a products table too wide to auto-broadcast.
- **The churn feature pipeline** from M2/M3: point-in-time cutoff, aggregations, window features, a broadcast join, a sort-merge join, labels, a training set.
- **Per-step monitoring**: jobs, stages, tasks, bytes, shuffle, spill and a skew ratio per step, from Spark's REST API, written as a ledger and a Markdown report. On GCP the same lines feed Cloud Logging metrics, a dashboard, an email alert and a BigQuery `run_ledger` table.
- **Google Cloud infrastructure as scripts**: project, network, bucket, BigQuery, least-privilege service account, budget, monitoring, a Cloud Workflow and a (paused) nightly Cloud Scheduler job.
- **17 architecture decision records** explaining every non-obvious choice, including the three things that only broke when run for real.

## Honest caveats

- The course was written in "light mode": Spark configuration defaults and version numbers come from the author's knowledge of Spark 3.x and were not re-checked against the official docs. Verify a number before quoting it in an interview.
- The lab's code has been run end to end at every scale listed above; its Spark settings are what worked, not what the docs recommend.
- The data is synthetic. Its distributions are realistic in shape, not in content.
